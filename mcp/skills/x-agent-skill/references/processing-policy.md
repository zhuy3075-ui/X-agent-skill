# 凭据、已有数据、任务路由与结果约定

本文描述当前版本可执行的工作流程。以实际 MCP 工具定义和任务结果为准。

## 凭据检查与存储

- 采集前确认用户已经提供凭据引用，对应 Worker 私有文件或环境值存在且可读取。
  注册过引用不等于文件中仍有值；本机只核实存在性，不显示 token。
  远程 Agent 无法读取配置时，明确说明需要用户在服务器配置，不虚构就绪接口。
- 缺凭据时不提交采集：说明尚未开始和安全配置方式。格式错误、文件损坏、失效或需解锁分别解释。
  数据库查询与已有数据分析不需要 X token，不触发网络登录检查。
- 用 mcp/credentials.py 隐藏输入保存到 mcp_credentials_file 对应的私有 JSON。
  键是 SCWEET_X_ACCOUNT_A 等引用，值只在采集端保存；普通 config 仅保存路径，技能 config 保存偏好。
  写入使用锁、受限临时文件、磁盘刷新与原子替换；失败保留旧文件并明确报错。
- Worker 按请求读取私有文件；配置文件已指定但损坏时不可静默回退。格式通过不代表登录有效。
  注册引用后执行 accounts_check，并由 jobs_get 核实检查结果。替换 token 重新检查身份。
- 配置多个不同账号可有界轮换。多个 token 属于同一 X 数字身份时不当作额外配额。

## 认证结论与缓存边界

当前没有跨任务共享的 30 分钟认证缓存保证。无需时不额外调用 accounts_check，
但不要把 checked_at 当作完整缓存证据，也不要承诺 Worker 不再验证。
成功读取数据库或命中已有数据不证明 X 登录有效；明确登录拒绝后不能继续复用旧结论。
需要严格保证校验最小间隔 30 分钟的场景，先说明当前能力不满足，不用对话记忆模拟后端机制。

## 已采集数据

- 唯一性由帖子／评论的平台数字 ID 判定；发布时间不能独立识别唯一记录。
  正文指纹用于比较内容变化，不用于合并不同 ID 的相似帖子。
- 完整记录以唯一 ID 更新，内容变化保留版本，互动按实际观测保存快照。
  同一请求重试使用原 request_id；参数改变或明确重做使用新请求标识。
- 先查目标、日期、类型、覆盖与观测时间。已存样本足以满足分析／导出时直接复用，注明范围。
  有记录不代表已完整；当前没有自动按覆盖区间跳过所有重复采集的保证。
- 只需更新数字时刷新指标；评论续采沿任务保存的分页分支，避免重新提交第一页。
  查询游标与 X 分页游标分开，不互相传递。缺失值不当作零，单次快照不产生增长结论。

## 未覆盖任务

先组合实际可用的工具，保持目标、权限和输入输出一致。无法组合时选择功能相近的已安装技能，
读取其定义再使用。普通参数缺失由默认值补齐；目标或交付存在关键歧义时最少量澄清。
确需修改服务或技能时，在用户本次实现授权范围内提出最小变更、验证和更新文档。
源码修改不等于部署，未发现的新工具不能声称已可调用；缺连接或主机权限时说明替代路径。

## 执行结果

每次尝试均说明成果、覆盖日期、完整性、真实原因和必要下一步。
排队不是成功，预算耗尽但已保存内容不是全部失败；同一任务重试不重复计数。
默认不显示内部任务 ID、partial 等状态码，也不让用户查看日志才能理解结果。
示例表达和错误翻译见 [结果表达约定](result-language.md)；分页与档案见
[分页与档案](pagination-archives.md)。真实异常不能因为隐藏术语而被隐瞒。
